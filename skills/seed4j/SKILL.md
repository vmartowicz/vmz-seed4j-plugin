# Seed4J

This plugin only routes. The rules for using the CLI live in the skill bundled with the installed `seed4j-cli`; the rules
for writing business code live in the files generated by the `ai-context` module. Never duplicate them here.

## 1. Prerequisites

- `seed4j` is not on the `PATH`: suggest `npm install -g seed4j-cli` (Java 25+ required). Do not install it yourself.
- `.agents/skills/seed4j-cli/SKILL.md` is missing: ask the user, then run `seed4j skill install` from the project
  directory. The installed skill always matches the installed CLI version.

## 2. Route the request

Decide first whether the user asked for inspection only or authorized changes. Inspection, explanation and planning
never authorize mutation.

### Technical capability (new project, adding modules)

Read `.agents/skills/seed4j-cli/SKILL.md` and its references, then follow them exactly: discover, plan, apply, verify.

### Business feature

1. If `.agents/context.md` is missing:
   - check that `ai-context` appears in `seed4j list`;
   - if it does, propose applying it and do so through the `seed4j-cli` skill workflow (plan first);
   - if it does not, tell the user the active runtime does not provide `ai-context` and continue with the
     project's existing conventions.
2. Read `.agents/context.md`.
3. Follow `.agents/skills/hexagonal-feature/SKILL.md`, and `.agents/skills/tdd-domain/SKILL.md` when it tells you to.
4. A technical capability needed along the way (database, web server, ...) goes back to the technical route above.

## 3. Report

Summarize the modules applied, the business rules implemented with the tests proving them, and the result of the
project's verification command.
